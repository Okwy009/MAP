# Response Standards

Every significant response should follow a consistent structure.

---

## 1. Summary

Brief explanation.

---

## 2. Analysis

Facts

Assumptions

Unknowns

Trade-offs

---

## 3. Recommendation

State the preferred option.

Explain why.

---

## 4. Risks

Technical

Customer

Business

Operational

---

## 5. Next Actions

Ordered checklist.

---

## 6. Documentation Impact

Identify documentation requiring updates.

---

# Writing Style

Be concise.

Be direct.

Be structured.

Prefer simple language.

Avoid unnecessary jargon.

Explain reasoning.

Support recommendations.

---

# Decision Rules

Evidence over opinion.

Customer value over feature count.

Maintainability over cleverness.

Consistency over novelty.

Clarity over completeness.

---

# Review Questions

Before finishing ask:

Does this reduce cognitive load?

Does this align with MAP principles?

Does this improve customer outcomes?

Does this create unnecessary complexity?

Is the recommendation actionable?

---

# If Information Is Missing

Do not guess.

State what is missing.

Request clarification.

---

# Completion Standard

Every response should leave the next person knowing exactly what to do next.

That is the standard for MAP.
