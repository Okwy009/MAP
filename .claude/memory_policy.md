# MAP OS — Memory Policy

Version: 1.0

Status: Active

Applies To: All Claude Agents

---

# Purpose

Memory allows MAP OS to improve over time.

The purpose of memory is not to remember everything.

The purpose is to remember what improves future decisions.

---

# Core Principle

Store knowledge.

Not conversations.

Store lessons.

Not noise.

---

# Sources of Memory

MAP OS learns from:

Decision Log

Architecture Decisions

Customer Insights

Competitor Insights

Product Learnings

Engineering Documentation

Playbooks

Release History

These documents form the institutional memory of MAP.

---

# Memory Hierarchy

1. Company Principles

2. Product Documentation

3. Decision Log

4. Knowledge Base

5. Current Conversation

Older strategic decisions outweigh temporary discussions unless explicitly revised.

---

# What Should Be Remembered

Major product decisions.

Validated customer insights.

Architecture decisions.

Recurring engineering patterns.

Lessons from releases.

Repeated customer pain points.

Successful workflows.

Approved terminology.

Changes to company principles.

---

# What Should NOT Be Remembered

Draft ideas.

Brainstorms.

Temporary opinions.

Unvalidated assumptions.

Personal preferences unless intentionally adopted.

One-off experiments without evidence.

Incomplete discussions.

Speculation.

---

# Memory Lifecycle

New Information

↓

Validate

↓

Determine Importance

↓

Assign Knowledge Category

↓

Update Relevant Knowledge Document

↓

Reference in Future Work

---

# Updating Memory

Memory should only change when:

A decision is approved.

Research validates an assumption.

Architecture changes.

Product direction changes.

A recurring pattern emerges.

A playbook changes.

Never update memory because of a single conversation.

# Memory Validation

Before updating memory ask:

Is this evidence-based?

Will this matter six months from now?

Does this improve future decisions?

Does this belong in an existing knowledge file?

If any answer is "No," do not update memory.

---

# Referencing Memory

When making recommendations:

Use previous decisions where relevant.

Avoid repeating rejected ideas.

Build upon established knowledge.

Respect historical context.

If a previous decision is being challenged:

Explicitly explain why.

---

# Memory Conflicts

If new evidence contradicts existing knowledge:

Do not overwrite immediately.

Create a new entry.

Document:

What changed.

Why it changed.

Supporting evidence.

Who approved the change.

Knowledge should evolve transparently.

---

# Memory Review

Review institutional memory:

After major releases.

After customer research.

After roadmap changes.

After architecture changes.

After quarterly planning.

Outdated knowledge should be marked as superseded—not deleted.

---

# Relationship to Documentation

Memory complements documentation.

Documentation explains the current state.

Memory explains how the current state came to be.

Both are required.

---

# Guiding Philosophy

MAP OS should become wiser with every decision.

Institutional knowledge is one of the company's most valuable assets.

The goal is not perfect recall.

The goal is better decisions tomorrow than yesterday.

Every update to memory should reduce uncertainty for the next person—whether human or AI.
